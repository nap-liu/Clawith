## 产品行为

- 同一 Agent 可以安装同名、同 URL、不同凭据/header/env 的私有 MCP。
  不同配置生成独立 server ID 和显示名后缀；未改变的 HTTP/stdio 配置重复
  导入复用安装，保留原工具启停状态。名称不包含凭据及其散列，也不从任意
  stdio 参数值猜名称。新增函数名不超过 64 字符。
- 公司/平台 MCP 共用同一工具目录。Agent 只能配置私有凭据、header、env
  和过滤工具启停；不能从 Agent 页面或对应 API 修改共享 URL、命令、参数、
  schema、说明或刷新共享目录。历史及场景中的越界定义覆盖在运行时失效。
- Agent 连接检查使用有效配置，不保存返回的工具目录或 instructions。
  对工具级配置不一致的共享安装，检查各套不同配置。
- 删除绑定要求 Agent 管理权限；共享目录不因最后一个绑定被移除而删除。
  平台禁用仍是 schema、清单、prompt 和实际执行的否决条件。
- 旧批量配置接口按精确 ID 或当前租户内无歧义的名称定位，不再按新 URL
  合并另一个目录。Smithery 导入与恢复使用独立连接及安装自己的 key；
  并发导入保留先提交的连接，不混写其他连接的发现结果或授权链接。

## 真实本地环境验证

使用任务自己的 PostgreSQL 15、API、前端和 Chromium 容器。API/前端挂载
本工作树；浏览器访问隔离网络命名空间的 `127.0.0.1:3008`，通过前端 `/api`
代理请求真实 API。未替换宿主共享 3008 栈，未操作生产。

独立 HTTP JSON-RPC MCP 服务实际接收 initialize、tools/list、tools/call。
调用通过产品 `execute_tool` 和真实执行子进程，未 monkeypatch provider：

| 验收流程 | 结果 |
| --- | --- |
| 同 Agent 依次用 A、B、A 配置导入 | 仅两个独立安装；实际调用分别得到 A/B 身份及对应 header |
| 两个 Agent 绑定同一共享工具，其中一个覆盖凭据 | 当前 Agent 使用私有身份，另一个仍使用共享身份 |
| 普通管理者尝试修改/刷新共享定义 | API 拒绝，数据库目录和共享凭据保留 |
| 保留旧 scene 快照后禁用平台工具 | 后续规范名/别名请求没有再到达 provider |
| 浏览器保存 B 凭据和 B header 后测试连接 | PUT 保存成功，实际 MCP 服务收到 B/B |
| 浏览器检查共享编辑器 | 无基础定义编辑、无 prompt 输入、无刷新工具按钮 |
| 浏览器检查私有安装 | 已安装分类显示原名及 `-2`；私有刷新入口可见 |

浏览器无 pageerror，已查看共享/私有编辑器截图。临时验收脚本及凭据留在
本地临时目录，没有提交到仓库。
